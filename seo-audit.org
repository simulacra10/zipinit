* Methodology

This is a 6-page static site with direct filesystem access, so it was audited
directly (file inspection + live HTTP/robots.txt checks against the
production domain) rather than via a full parallel subagent crawl. No Search
Console, PageSpeed API, or DataForSEO credentials were available, so CWV and
backlink numbers are inferred from markup weight, not measured — flagged
where that matters. Findings apply to both the live site (branch =main=) and
the unreleased redesign (branch =wip=), since neither touched meta tags,
schema, or robots.txt.

* Framing

Standard SEO logic (keyword volume, conversion funnels, commercial intent)
does not map cleanly here. The site's actual objective, per its own Charter,
is to get specific people — Maryland legislators, journalists, civic
reformers — to engage with one argument, and ideally to be cited and
summarized accurately by search and AI systems doing that argument justice.
That reframes the priority stack: AI-crawler access and citability (GEO)
matter more than typical keyword ranking, and "authority" here looks like
earned citations from press, government, and Wikipedia rather than
commercial backlinks.

With that lens applied, one finding below is a genuine showstopper.

* Critical

** 1. Cloudflare is blocking the exact AI crawlers this site was built to attract

The repo's own =robots.txt= just says =Allow: /=. But Cloudflare's proxy
injects a "Managed content" block in front of it on the live domain that adds
=Disallow: /= for =GPTBot=, =ClaudeBot=, =Google-Extended=,
=Applebot-Extended=, =Amazonbot=, =Bytespider=, =CCBot=, and
=meta-externalagent=. That's OpenAI's, Anthropic's, and Google's AI
crawlers — Google-Extended specifically governs Gemini / AI Overviews
grounding.

Meanwhile the site has genuinely excellent AI-citation infrastructure:
=ai.txt=, =llms.txt=, a dedicated =/ai/= directory with canonical summaries,
and an explicit "Guidance for Language Models" section. None of it can be
read by the systems it's addressed to, because they're blocked at the door.

- *First principle:* crawl access is the precondition for citation. No
  amount of well-written =llms.txt= matters if the crawler can't fetch the
  page.
- *Dependency:* blocks every other AI-readiness improvement below — fix
  this first, everything else in that category is currently wasted effort.
- *Falsifiability:* re-fetch =https://zipinit.org/robots.txt= and confirm no
  =Disallow: /= remains for those user-agents; separately, ask
  ChatGPT/Claude/Perplexity "what is ZIP apportionment" over the following
  weeks and see if zipinit.org starts getting cited.
- *Leading indicator:* GoatCounter referrer log showing traffic from
  chatgpt.com, perplexity.ai, or a Google AI Overview surface.
- *Where to fix it:* Cloudflare dashboard -> zone -> Bots / AI Crawl Control
  (or "Content Signals" settings) — a toggle, not a code change.

** 2. Stale backup files are live and publicly indexable

=index.html.bak= and =static/style.css.bak= are committed to git and serving
at =zipinit.org/index.html.bak= / =zipinit.org/static/style.css.bak= — a
stale, lower-quality duplicate of the homepage reachable by any crawler.

- *First principle:* unlinked isn't unreachable — anything not blocked and
  not 404 is fair game for a crawler.
- *Dependency:* same root cause as the canonical-URL issue below (#3) — fix
  together.
- *Falsifiability:* confirm 404 at both URLs after removal.
- *Fix:* =git rm index.html.bak static/style.css.bak=, add =*.bak= to
  =.gitignore=.

* High

** 3. No canonical tags; sitemap lists / and /index.html separately

Classic split-authority setup for the homepage itself.

- *First principle:* search engines need one canonical URL per unique page
  to consolidate signal.
- *Dependency:* pair with #2 (same "too many reachable copies" root cause).
- *Falsifiability:* Search Console should show one indexed homepage, not
  two.
- *Fix:* add =<link rel="canonical" href="...">= (adjusted per page) to
  every template; drop the =/index.html= entry from =sitemap.xml=.

** 4. Zero structured data anywhere

No =Organization=, =WebSite=, =Article=, or =DefinedTerm= schema — despite
the project coining a term ("ZIP apportionment") it explicitly wants to own
as canonical.

- *First principle:* schema.org JSON-LD is the most universally-parsed
  machine signal for entity attribution — it's how a term gets confidently
  linked to its originating source instead of guessed at from prose.
- *Dependency:* directly extends the =ai.txt=/=llms.txt= work already
  done — those files already assert =canonical_term: ZIP apportionment= in
  prose; =DefinedTerm= + =Organization= JSON-LD says the same thing in a
  format Google's Knowledge Graph pipeline actually ingests.
- *Falsifiability:* validate with Google's Rich Results Test (zero errors),
  then watch whether the term starts surfacing zipinit.org as a source.
- *Leading indicator:* Search Console's "Enhancements" report picks up the
  new types after the next crawl.

** 5. Only the homepage has Open Graph / Twitter Card tags

=brief.html=, =charter.html=, =essay.html=, and
=representation-is-broken.html= render as bare links with no title/image
when shared in Signal, iMessage, Slack, etc.

- *First principle:* this site's actual distribution model is peer-to-peer
  sharing ("share it with a legislator, journalist, or organizer") — the
  share-card preview is the first impression for that strategy, arguably
  more than the SERP snippet.
- *Fix:* copy the homepage's OG/Twitter block to the other four pages with
  page-specific title/description; reuse =preview.png= or make per-page
  images later.
- *Falsifiability:* paste each URL into a messaging app or a Card Validator
  and confirm a real preview renders.

** 6. essay.html title tag is 96 characters

Will truncate mid-phrase in search results (Google's render limit is
roughly 55-60 characters).

- *Fix:* shorten to something like "ZIP Apportionment: Restoring Proximity
  and Scale – ZIP Apportionment Initiative" (~78 chars, still worth
  trimming further, or drop the site-name suffix on this one page).

** 7. representation-is-broken.html has no meta description

Google will auto-extract a fragment from the punchy, line-broken body copy,
which may read oddly out of context.

- *Fix:* one sentence, e.g. "A short film and essay on why U.S.
  representation stopped scaling to real communities — and what to do about
  it."

* Medium

** 8. Embedded video has no captions track

A matching =.srt= file already exists in the repo
(=mp3-mp4/representation-is-broken/representation-is-broken.srt=) but isn't
wired in. Add =<track kind="captions" src="...srt" srclang="en">=. Both an
accessibility fix and a real AI/search-readability win — transcripts are
what let text-based crawlers "watch" the video.

** 9. Video src has an unencoded space

=REPRESENTATION IS BROKEN.mp4= while the sibling =.mp3=/=.srt= use clean
lowercase-hyphenated names. Browsers auto-encode it so it likely still
plays, but it's fragile and worth normalizing while already touching that
markup for #8.

** 10. preview.png (OG image) is 1.3MB for a 1200x630 PNG

Correctly sized, but 10-20x heavier than needed. Doesn't hurt on-page CWV
(never rendered in-page) but slows link-preview generation on some
platforms. Re-export as an optimized JPEG/PNG, target under 150KB.

** 11. No provenance / "who's behind this" content

Beyond the Charter's abstract language. For civic-reform content,
transparency about who's speaking is itself a trust signal, independent of
argument quality — and it doesn't have to contradict the Charter's explicit
anti-branding stance (Article VII). A short paragraph would do it; doesn't
need a whole page.

** 12. No HSTS header live

The HTTP -> HTTPS redirect works correctly, but no
=Strict-Transport-Security= header is present. Minor hardening gap —
closeable via Cloudflare's Edge Certificates -> HSTS toggle, no code
change.

* Low

** 13. present.html is fully orphaned

New reveal.js deck on =wip= — empty description/keywords, not in
=sitemap.xml=, not linked from anywhere, and the only page pulling a
stylesheet from a third-party CDN (jsdelivr), a small inconsistency with the
site's otherwise self-contained, no-third-party-request posture. Decide if
it's meant to be public; if yes, link it and add it to the sitemap.

** 14. Sitemap-listed but not internally linked assets

The pamphlet HTML/PDF, =zip_apportionment_essay.md=, and the essay PDF.
Sitemap presence helps indexing, but internal links carry the actual
relevance signal. Cheap fix: link the PDF/markdown from =essay.html=, link
the pamphlet from =representation-is-broken.html=.

* What to Do First

1. Fix the Cloudflare AI-bot block (#1) — dashboard setting, five minutes,
   highest leverage on this list by far given the site's actual goal.
2. Remove the =.bak= files and add canonical tags (#2, #3) — same session,
   same root cause.
3. Add =DefinedTerm=/=Organization= schema (#4) and per-page OG tags (#5) —
   reinforces the term-ownership goal now that crawlers can actually reach
   it.
4. Everything else is genuinely optional polish, not blocking anything.
